Experiment objectives

  • Understand the difference between a master key and a session key.
  • Observe how AES-GCM protects a session key.
  • Encrypt and decrypt a user-entered message.
  • Verify that the recovered key and message match the originals.
1. Introduction

Symmetric key distribution is the process of securely sharing a secret key between communicating parties so that they can encrypt and decrypt information. AES (Advanced Encryption Standard) is a symmetric encryption algorithm that uses the same key for encryption and decryption.

In this experiment, a master key protects a temporary session key. The receiver recovers the session key and uses it to encrypt and decrypt the user's message with AES-GCM. GCM provides confidentiality and integrity verification through an authentication tag.

3. Procedure
  1. Enter a plaintext message in the experiment section.
  2. Generate a random 256-bit master key.
  3. Generate a random 256-bit session key.
  4. Encrypt the session key with the master key using AES-GCM.
  5. Keep the nonce and authentication tag for session-key recovery.
  6. Simulate the receiver decrypting and verifying the session key.
  7. Encrypt the user's message with the recovered session key and a fresh nonce.
  8. Decrypt and authenticate the ciphertext.
  9. Compare the original and recovered session key and message.
4. Applications
  • Secure messaging: protects message contents between users.
  • File encryption: protects documents, backups, and shared files.
  • Network security: symmetric encryption protects bulk data after secure session establishment.
  • Database security: encrypts sensitive stored information.
  • IoT communication: protects data exchanged by securely provisioned devices.
  • Key management: key-encryption keys protect data-encryption keys.

7. Conclusion

Symmetric key distribution using AES was demonstrated by generating a master key and session key, encrypting the session key using AES-GCM, and recovering it at the receiver. The recovered session key was then used to encrypt and decrypt the user-entered message. When both verification checks are TRUE, the recovered key and message match their original values.

Security note: keys are displayed only for educational purposes. Do not display or log keys in real applications. Production systems need secure, authenticated key establishment.
